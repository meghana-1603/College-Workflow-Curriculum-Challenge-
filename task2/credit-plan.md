## 2. Credit-change principles

1. Preserve core programming, algorithms, mathematics, databases, computing systems and AI foundations.
2. Prioritize improving assessments within existing courses before proposing additional credits.
3. Propose new credit-bearing courses only when a genuine learning gap is established and the university approves the change.
4. Avoid counting alternative electives as additional credits when students choose only one option.
5. Count each selected existing course only once in the gross affected-credit calculation.
6. Distinguish credits affected by proposed assessment updates from credits added to or removed from the programme.
7. Treat all proposed changes as recommendations until reviewed and approved by the university.

## 4. Gross affected credits and net credit change

**Gross affected credits** are the listed credits of existing courses selected for proposed updates, with each course counted once.

**Net credit change** is the number of credits added minus the number of credits removed.

| Measure | Calculation | Result |
|---|---|---:|
| Overall academic baseline | Supplied programme baseline | 166 |
| Courses marked UPDATE | Count of selected courses | 11 |
| Gross affected credits | Sum of selected course credits | 36 |
| Affected-credit share | 36 ÷ 166 × 100 | 21.69% |
| New credits proposed | No new credit-bearing courses | 0 |
| Credits removed | No reductions proposed | 0 |
| Net credit change | 0 − 0 | 0 |
| Proposed overall total | 166 + 0 − 0 | 166 |

\[
\text{Affected-credit share}
=\frac{\text{Gross affected credits}}{\text{Overall academic baseline}}\times100
\]

\[
=\frac{36}{166}\times100=21.69\%
\]

The proposed plan covers approximately **21.69% of the overall academic credit baseline**, within the target range of 20–25%.

This percentage represents the credits associated with courses selected for proposed assessment updates. It does not mean that 36 new credits are being added or that 36 credits have already been changed.

## 6. Proposed learning and assessment improvements

### 6.1 Software development and web applications

For DS202 and CS205, students could submit a small application with version-control history, input validation, automated tests and evidence of error handling. Assessment should focus on correctness, maintainability, security and reproducibility.

### 6.2 Machine learning and deep learning

For DS304 and DS306, students could document data splitting, evaluation metrics, baselines, error analysis and limitations. Assessment should reward justified evaluation choices and reproducible results rather than accuracy scores alone.

### 6.3 Data quality and big-data pipelines

For DS305 and DS307, students could document missing-value handling, schema checks, duplicate detection, pipeline failures and validation results. Assessment should consider reliability and traceability as well as successful execution.

### 6.4 Special project

For SP301, students could maintain a clear problem statement, acceptance criteria, version-control history, tests, known limitations and a concise demonstration. The scope should remain appropriate to the approved project.

### 6.5 Natural language processing and reinforcement learning

For DS311 and ML303, students could report evaluation methods, relevant baselines, error analysis and reproducibility limitations. Assessment requirements should reflect each course's learning outcomes and technical level.

### 6.6 Cloud computing and generative AI

For CS307, students could demonstrate access control, monitoring, cost awareness and recovery planning. For DS408, students could document prompts, verify generated claims, test outputs against criteria and discuss risks and limitations.

## 7. Prerequisites and feasibility

1. Programming and data-structure foundations should precede larger software-development and pipeline projects.
2. Database and web/API fundamentals should precede the workflow-tracker lab.
3. Data-cleaning and database skills should precede end-to-end data-pipeline work.
4. Machine-learning foundations should precede advanced AI evaluation projects.
5. Project requirements should reflect available teaching time, infrastructure and student preparation.
6. Any new credit-bearing course or module would require review of university regulations, workload, prerequisites and approval procedures.
7. This proposal adds no credits and removes no credits.

## 8. Implementation and review

The proposed updates should be reviewed against official course descriptions, learning outcomes and existing assessments. Only changes that address a demonstrated gap should be adopted. Assessment rubrics and evidence requirements should be defined before implementation, with pilot results and feedback considered before wider adoption.

Any change in the selected courses or their credit values would require recalculation of the affected-credit share. Proposed changes should not be described as implemented or approved without evidence of institutional authorization.

## 9. Limitations

- Credit calculations use the supplied course-and-credit information as the planning baseline.
- Proposed assessment changes have not been approved by the university.
- Existing syllabi and assessments must be checked before concluding that a topic is missing.
- No measured improvement in student performance, time savings or graduate employability is claimed.
- No new credits or reductions are proposed.
- The 21.69% figure measures credits associated with the 11 selected courses; it does not represent content already changed or verified as deficient.
- The 166-credit planning baseline comprises 163 credits from the listed Semester I–VIII courses and 3 credits for IP201 — Internship-I. Internship-I is part of the academic programme; official batch-specific verification remains necessary.
## 10. Conclusion

The proposed 2030 redesign prioritizes assessment quality and practical evidence over increasing the programme's credit load. It selects 11 existing courses representing 36 credits, equivalent to 21.69% of the 166-credit overall academic baseline.

The plan proposes no additional credits and no reductions, so the planned overall total remains 166 credits. All changes remain recommendations pending review of the applicable official curriculum, existing assessments and university approval requirements.
